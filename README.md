# full-stack-guide

> 一句话概括：这是一个面向全栈工程师的系统性学习与面试准备笔记库，按主题沉淀「原理 + 源码 + 工程取舍 + 面试表达」四层内容。

仓库不是速查手册的堆砌，而是希望每篇文档都能回答三个问题：**它是什么、它的边界在哪、在真实项目里该怎么用**。因此文档普遍采用「一句话结论 → 机制展开 → 边界与代价 → 实践与追问」的组织方式，并配有表格、示意图和可直接运行的示例。

## 如何使用

- **按主题顺序读**：先读「面试题总结」建立整体认知，再读「跳表与有序集合」深挖底层实现。
- **按问题查**：面试题文档的目录与文末「一页速记」可直接定位考点，适合临场复习。
- **对照源码读**：跳表笔记中的结构体与关键函数均标注了 Redis 7.x 的 `server.h`、`t_zset.c` 出处，建议边读边看源码。
- 文档中的 mermaid 图需要支持 mermaid 的 Markdown 阅读器（GitHub、Typora、VS Code 插件等）才能正常渲染。

## 写作约定

新增文档时遵循以下约定，保持全库风格一致：

1. **开篇一句话概括**：用一段引用块说清这篇文档解决什么问题。
2. **给出阅读路线**：用表格区分初级 / 中级 / 高级 / 选型读者的关注章节，再列目录。
3. **表格优先**：对比、速查、复杂度、命令清单尽量用表格表达。
4. **讲清边界**：不仅写「怎么用」，还要写「什么时候不成立、代价是什么」。
5. **理论与实践结合**：关键结论配示意图、源码片段或可运行示例，面试类内容附追问方向。
6. **文末速记**：用几句话或一页内容帮助读者快速回忆。
